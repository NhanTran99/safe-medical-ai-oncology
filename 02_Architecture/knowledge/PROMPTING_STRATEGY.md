1. PURPOSE

This document defines the Prompting Strategy of the Safe Medical AI System for Oncology Patient Education.

Unlike conventional prompt engineering approaches, the Prompting Strategy does not determine clinical behavior. Instead, it provides a standardized communication interface between governed system components and downstream Large Language Models.

2. DESIGN PHILOSOPHY

The Prompting Strategy follows the following principles:

Governance before prompting
Structured inputs before free-text prompts
Minimal prompts
Model-independent prompt specification
Reproducible prompt construction
Explainable prompt composition
3. ROLE WITHIN THE SYSTEM

Prompting Strategy is responsible for:

assembling standardized prompts;
communicating structured system decisions to the LLM;
preserving architectural consistency.

Prompting Strategy is not responsible for:

clinical reasoning;
safety decisions;
evidence retrieval;
workflow determination.

These responsibilities belong to upstream components.

Prompt generation occurs only after all governance and knowledge components have completed their responsibilities.

5. STRUCTURED PROMPT ASSEMBLY

Prompts are assembled from structured architectural artifacts rather than manually engineered free-text instructions.

Primary inputs include:

Navigation Context
Safety Decision Card
Evidence Package

The Prompt Builder integrates these components into a standardized Prompt Specification.

6. PROMPT BUILDER

The Prompt Builder is responsible for:

validating required inputs;
enforcing the Prompt Contract;
assembling Prompt Specification;
maintaining prompt consistency.

The Prompt Builder remains independent of any specific language model.

7. PROMPT LAYER ARCHITECTURE

Prompt Specification consists of four logical layers.

System Layer

Defines system identity and operational context.

Governance Layer

Communicates permissions, restrictions, and safety requirements.

Evidence Layer

Provides the Evidence Package generated by the RAG subsystem.

Communication Layer

Defines patient-centered communication style and educational presentation requirements.

8. PROMPT MINIMALISM

Prompt Specification shall contain only the information required for response generation.

Medical knowledge remains external to the prompt and is supplied through the Evidence Package.

This principle minimizes unnecessary prompt complexity and improves maintainability.

9. MODEL INDEPENDENCE

Prompt Strategy defines a logical specification rather than model-specific prompts.

Implementations for GPT, Claude, Gemini, or future language models remain downstream implementation responsibilities.

10. PROMPT VERSIONING

Prompt Specifications are independently version controlled.

Versioning supports:

reproducibility;
evaluation;
implementation tracking;
future optimization.
11. PROMPT LOGGING

Every Prompt Builder execution generates a Prompt Record.

Illustrative metadata include:

Prompt Version
Navigation Context Identifier
Safety Decision Identifier
Evidence Package Identifier
Generation Timestamp

Prompt logging supports reproducibility and evaluation without requiring storage of complete prompts.

12. PROMPT CONTRACT

The Prompt Builder enforces a Prompt Contract.

Mandatory inputs include:

Navigation Context
Safety Decision Card
Evidence Package

Prompt construction shall not proceed if mandatory architectural artifacts are unavailable.

13. RESPONSE COMPOSITION

Responses generated by the LLM follow a standardized composition.

Illustrative structure includes:

Educational Answer
Evidence Explanation
Important Notes
Safety Advice
References

The exact presentation may vary according to implementation while preserving logical consistency.

14. OUTPUT CONTRACT

All generated responses are evaluated against an Output Contract.

Illustrative requirements include:

educational consistency;
evidence consistency;
safety compliance;
citation completeness;
structural completeness.

Responses failing Output Contract validation shall undergo downstream validation or regeneration before delivery.

15. ARCHITECTURAL PRINCIPLES

The Prompting Strategy follows:

Deterministic prompt construction
Minimal prompting
Contract-driven communication
Separation of concerns
Explainable interfaces
Model independence
