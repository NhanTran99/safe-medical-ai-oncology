## Locked Decisions
### A1 — Phase 5 scope and structure
- Phase 5 transforms the verified/governed knowledge repository into an implemented, integrated, validated Safe Medical AI capability.
- Internal workstreams:
  - 5A System Implementation
  - 5B System Integration & Functional Validation
  - 5C Clinical & Safety Validation
- Primary outputs include working chatbot/system capability, retrieval/runtime integration, Runtime Evidence Package, output validation, technical/clinical/safety validation evidence, and Phase 5 closure evidence.

### A2 — Entry/exit and execution
- Entry requires accepted Phase 4 baseline, approved Phase 5 scope, required governance dependencies PASS or formally dispositioned, accepted architecture baseline, and implementation authority/tooling.
- Phase 5 execution sequence:
  5A implementation → 5B retrieval/runtime integration → 5C evidence/output validation → technical validation → clinical/safety validation → remediation/re-validation → closure.
- Phase 5 PASS requires implementation, integration, technical validation, clinical/safety validation, traceability, critical-defect closure, and residual-risk disposition.
- Phase 6 is Deployment Readiness.

### A3 — Responsibility and Claude Code boundary
- ChatGPT/Strategist: strategy, governance, architecture, validation design, review.
- Claude Code: implementation, technical execution, tests, technical evidence.
- User/Project Coordinator: approval of governance decisions, major scope/architecture/phase/release decisions.
- Claude Code has no independent authority over clinical scope, governance, safety policy, Phase gates, Retrieval Ready, or release authorization.
- Claude receives an approved Master Handover before task-specific prompts.
- First Claude task is Repository/Implementation Readiness Assessment, not chatbot construction.
